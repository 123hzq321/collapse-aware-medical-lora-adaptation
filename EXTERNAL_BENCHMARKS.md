# External Generalization Extension

This extension addresses the main weakness of the earlier draft: the PubMedQA test100 slice is too small to support a broad claim about medical adaptation. The strengthened design separates three questions:

1. Does collapse-aware LoRA adaptation still help when PubMedQA is evaluated on all labeled examples via 5-fold evaluation?
2. Does the adapted model transfer across unseen medical exam subdomains?
3. Does medical adaptation preserve nonmedical yes/no QA and textual entailment behavior?

## Benchmark Suite

| Layer | Benchmark | Task type | Why it is included |
|---|---|---|---|
| In-domain biomedical QA | PubMedQA pqa_labeled all examples, 5-fold | yes/no/maybe | Replaces the fragile 100-example test slice with all labeled PubMedQA items. |
| Medical subdomain transfer | MMLU medical/biomedical subsets | A/B/C/D | Tests anatomy, clinical knowledge, college biology, college medicine, medical genetics, and professional medicine. |
| Biomedical external QA | BioASQ yes/no | yes/no | Optional external biomedical QA set with a different challenge pipeline; use official task packages. |
| Clinical reasoning | MedNLI | entailment/contradiction/neutral | Optional credentialed clinical NLI set; useful because the answer format differs from QA. |
| Nonmedical QA retention | BoolQ validation | yes/no | Checks whether medical adaptation damages general yes/no QA behavior. |
| Nonmedical NLI retention | GLUE RTE validation | entailment/not_entailment | Checks whether adaptation damages general textual entailment. |

## New Reproducible Artifacts

- `configs/external_benchmarks.yml`: benchmark manifest with task types, labels, sources, access notes, and export commands.
- `scripts/export_external_benchmarks.py`: exports PubMedQA 5-fold files and public Hugging Face benchmark files into a unified JSONL schema.
- `scripts/run_external_eval.py`: evaluates any exported file and writes raw predictions, summary metrics, per-class precision/recall/F1, prediction counts, dominant-label rate, entropy, and collapse flag.
- `data/external/README.md`: generated benchmark inventory with row counts.

## Commands

```powershell
$env:PYTHONPATH='src'

# Always available from the existing local PubMedQA split files.
.\.venv\Scripts\python scripts\export_external_benchmarks.py --tasks pubmedqa_5fold

# Public benchmarks. If local `datasets`/`pyarrow` is blocked, the exporter falls back
# to Hugging Face datasets-server rows API.
.\.venv\Scripts\python scripts\export_external_benchmarks.py --tasks mmlu_medical boolq rte

# Example evaluation command.
.\.venv\Scripts\python scripts\run_external_eval.py `
  --model Qwen/Qwen2.5-0.5B-Instruct `
  --data-file data\external\mmlu_medical_test_seed42.jsonl `
  --out runs\external_mmlu_medical_qwen05b_base.jsonl
```

## Reporting Rule

Do not describe model performance on the external suite until each model condition has raw predictions and metrics files. The datasets themselves are now exported locally, but the model-result tables still need to be generated by `scripts/run_external_eval.py`.

For PubMedQA, avoid train-test contamination: `pubmedqa_labeled_all_seed42.jsonl` contains the original local train/dev/test rows. A valid all-example PubMedQA result must train on each fold train file and evaluate only on the paired held-out fold test file. Existing adapters trained on the original 800-row split should be compared on the original held-out test or on external datasets such as MMLU, BoolQ, and RTE.

Primary sources checked while adding the suite: PubMedQA official site, Hugging Face `cais/mmlu`, BioASQ official site, PhysioNet MedNLI, Google Research BoolQ, and GLUE benchmark RTE.
